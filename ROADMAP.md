# Roadmap

Este documento recoge propuestas de evolución de la guía. Los elementos de esta lista son trabajo pendiente, no contenidos ya implementados. Las prioridades pueden cambiar según las necesidades de aprendizaje y mantenimiento.

La clasificación por nivel indica dónde encajaría cada mejora en el [itinerario de aprendizaje](docs/itinerario-aprendizaje.md); no significa que el nivel esté completo ni que el contenido sea un requisito obligatorio.

## En curso

### Nivel 2 · Desarrollo estructurado

- [ ] Completar y validar el laboratorio 03 con un proyecto Python reproducible, pruebas y una incidencia acotada.

### Transversal · Mantenimiento de referencias

- [ ] Revisar periódicamente las equivalencias entre herramientas y sus enlaces oficiales cuando cambien sus modalidades o configuraciones.

## Propuestas pendientes

### Nivel 2 · Desarrollo estructurado

- [ ] Practicar el uso de IA con criterios de aceptación, pruebas, revisión de cambios e integración continua, con una tarea verificable y un resultado reproducible.

### Nivel 3 · Configuración del entorno

- [ ] Añadir ejemplos comparativos de instrucciones, reglas, skills, hooks y MCP en las principales herramientas. Distinguir las equivalencias conceptuales de las capacidades que no tienen correspondencia directa.

### Nivel 4 · Ingeniería asistida

- [ ] Desarrollar un laboratorio sobre documentación del ciclo de vida: requisitos, historias de usuario, casos de uso, ADR, tareas y documentación técnica.
- [ ] Definir una forma ligera de registrar resultados, limitaciones y decisiones derivadas de cada laboratorio, con trazabilidad entre necesidad, cambio y verificación.

### Nivel 5 · Gobierno y escalado

- [ ] Ampliar los ejemplos de seguridad: secretos, permisos, prompt injection y ejecución de acciones externas.
- [ ] Incorporar un ejercicio de evaluación de calidad, coste y utilidad de asistentes en un flujo de trabajo, con criterios comparables y limitaciones documentadas.

## Criterios para aceptar cambios

- Aporta un aprendizaje práctico o resuelve una necesidad identificada.
- Se puede verificar con documentación oficial, pruebas o criterios de aceptación explícitos.
- Evita duplicar contenidos que ya tienen una ubicación canónica en la guía.
- Mantiene el enfoque agnóstico respecto a proveedores y explica las diferencias cuando no existe equivalencia directa.
- Protege credenciales, datos de clientes y código confidencial.
- Se mantiene proporcionado al nivel del itinerario y al esfuerzo de mantenimiento.
- Identifica el objetivo de aprendizaje, el nivel recomendado y la evidencia con la que se comprobaría el resultado.

Para proponer una mejora, explica el problema que resuelve, el archivo afectado y cómo se comprobaría el resultado. Consulta el [mapa de contenidos](docs/mapa-contenidos.md) para localizar la sección pertinente y el [diseño de ejercicios](docs/estructura-ejercicios.md) para aplicar la plantilla editorial.
